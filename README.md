# 基金买入工作台

一个**本地运行的基金操作辅助工具**：记录每一次买入与卖出，并把买卖点标注在真实净值曲线上，帮助判断每次加仓相比上次是**追高**还是**抄底**、当前净值相对前次买入/卖出的涨跌幅、均线位置与区间回撤。

- 全程本地运行，数据只存在你自己电脑上，不上传云端
- 零外部依赖：无需 `npm install`，页面无框架、无 CDN、无外链字体
- 净值数据来自天天基金（东方财富）公开接口

> 本文档为**唯一文档**，同时覆盖：面向使用者的操作说明 · 项目门面介绍 · 面向开发者的架构、算法、验收与维护须知。原 `使用说明.md` 与 `交接文档.md` 已并入本文。

## 一、项目简介

### 1.1 项目定位

一个**本地运行的基金操作辅助工具**，用于记录个人对基金的买入与卖出，并把操作点位标注在真实净值曲线上，帮助判断：

- 每次加仓相比上一次买入，是**追高**还是**抄底**
- 当前净值相对**前次买入 / 前次卖出**的涨跌幅（两个独立口径，不计算总体盈亏）
- 净值与 **顾比均线（GMMA）** 的相对位置，并给出参考操作建议
- 任意交易日在**当前所选时间段内**的回撤深度

### 1.2 技术形态

| 项 | 说明 |
|---|---|
| 形态 | 本地 Web 应用：本机启动 Node 服务，浏览器访问 `http://127.0.0.1:8765` |
| 前端 | 单文件 HTML（`public/index.html`），CSS/JS/图表/图标**全部内联**，零外部依赖 |
| 后端 | `server.js`，仅使用 Node 内置模块（`http`/`https`/`fs`/`path`/`url`），**无需 npm install** |
| 数据源 | 天天基金（东方财富）公开接口，由本地服务代理转发，规避浏览器跨域限制 |
| 存储 | **记录与净值缓存分离**：`data/records.json`（不可再生，带 rev 并发校验 + 自动快照 + localStorage 兜底）、`data/navCache.json`（可再生，单只增量写入） |
| 安全 | 仅监听 `127.0.0.1`；校验 `Host`/`Origin`，拒绝非本机页面的跨源读写；不下发任何 CORS 响应头 |
| 运行依赖 | Node.js（`C:\Program Files\nodejs` 或 PATH 中任意可用的 node） |

### 1.3 范围外（明确不做）

- **不做**登录与账号体系
- **不做**手机端的专门交互规则（页面本身是响应式的，窄屏可用，但不为移动端做特殊交互设计）
- **不做**管理后台、浏览器通知/系统推送、云端同步、视频/大文件存储

## 二、功能特性

### 2.1 功能清单（共 11 项）

| # | 功能 | 说明 |
|---|---|---|
| 1 | 基金选择与净值加载 | 输入 6 位基金代码或名称片段搜索；加载该基金**成立以来全部历史净值** |
| 2 | 我的基金（表格管理） | 列出所有已加载/有记录的基金，支持切换、置顶、拖拽排序、按数值排序、更新、删除 |
| 3 | 买卖记录 | 记录每笔**买入/卖出**（日期、金额、备注），自动匹配当日净值并计算份额 |
| 4 | 批量新增 | 一次为**多只基金**添加相同的买入或卖出记录 |
| 5 | 批量管理 | 跨基金选择记录，批量改日期/改金额/改备注/删除 |
| 6 | 净值图表 | 净值曲线 + 买卖点标注 + 均线 + 区间切换 + 悬停详情 |
| 7 | 数据概览 | 操作笔数、投入本金（含卖出回款）、相较于前次买入、相较于前次卖出（共 4 张卡） |
| 8 | 数据持久化与备份 | 本地文件 + localStorage 双写；JSON 导出/导入；删除二次确认 |
| 9 | 数据源详情跳转 | 我的基金表格每行「详情」按钮 → 新标签页打开数据源站点（天天基金）的该基金详情页 |
| 10 | 前次操作涨跌幅口径 | 统一以「最新净值 vs 最后一次买入 / 最后一次卖出」计算涨跌幅（含分红），无记录留空；图表无同类前次操作时以所选区间首日为基准 |
| 11 | 待办提醒可忽略 | 「今天要处理」的每条提醒可一键忽略（不再常驻页面），支持全部忽略与恢复；忽略按「情境指纹」生效，数据变化后自动失效 |

### 2.2 收益口径（重要）

本工具**不计算总体盈亏**，只看「**当前净值相对上一次操作点**」涨了多少、跌了多少，两个口径：

- **相较于前次买入** = 最新净值 ÷ 最后一次买入的当日净值 − 1
- **相较于前次卖出** = 最新净值 ÷ 最后一次卖出的当日净值 − 1

没有买入（或卖出）记录时，对应位置**留空显示 —**。所有涨跌幅都按**含分红的复权口径**计算（用累计净值扣掉分红除权的影响）。

> 例：最后一次买入价 1.000、最后一次卖出价 1.200、最新净值 1.100 → 相较于前次买入 +10.0%，相较于前次卖出 -8.3%。

口径约定：

- 涨跌幅与盈亏**含分红**（按累计净值复权）；分红后单位净值会下跌，若只看单位净值会把分红误判成亏损或"抄底"（例：某基金单位净值 0.84 / 累计净值 11.2，纯净值口径会得出荒谬的 -92%）
- **份额按单位净值折算**（真实买入价，不含申购/赎回费）
- 均线与最大回撤仍为**单位净值口径**，分红除权日会有跳空
- 上游未提供累计净值时自动退化为单位净值口径，不崩、不误报

### 2.3 图表能告诉你什么

图表横轴是日期、纵轴是单位净值，折线是基金的真实净值曲线。每个买入点（红圆点）与卖出点（橙菱形）旁都会标**两行**数字：

```
买 +15.0%      ← 相对「上一次买入」
卖  -9.1%      ← 相对「上一次卖出」
```

- **买** 行 = 该点净值相对**上一次买入**点（追高为红、抄底为绿；颜色只作用于数字）
- **卖** 行 = 该点净值相对**上一次卖出**点
- 若某一边没有"上一次"（比如第一笔买入没有更早的买入），基准自动取**当前所选时间段的第一个交易日**，该行会标出区间名，例如 `买(近3月) +4.2%`；若基准就是该点自己，显示 `基准`（不显示 0.00%）
- **买入点**：红色圆点；**卖出点**：橙色菱形（颜色不再承载涨跌语义）

**标签自动避让**：标签位置由纯函数 `placeMarkerLabel()` 统一布置——优先放在标记点的四象限，按递增间距（10/16/24/34px）向上/向下叠排，取第一个「不越界、不压曲线、不压标记点、不压已放标签」的位置；全部被占时退化为遮挡最少的候选。只有当多笔操作挤在同几天时才可能出现轻微重叠（把鼠标悬停到点上可看清明细）。

**均线（两档可切，默认顾比）**：

| 模式 | 内容 |
|---|---|
| **顾比均线（默认）** | 短期组 EMA 3/5/8/10/12/15（青色 `#22d3ee` 组带 + 6 条细线）、长期组 EMA 30/35/40/45/50/60（品红 `#e879f9` 组带 + 6 条细线）；金叉标红▲、死叉标绿▼（可见区间内最近 8 个） |
| **关闭** | 只看净值曲线与买卖点 |

**顾比买卖建议**（仅顾比模式下，图例下方）：以最新净值为评估点，按规则链输出 买入 / 持有 / 观望 / 减仓 / 卖出 建议与理由，依据包括：价格相对长期组的位置（支撑/压力）、两组均线方向（斜率）、短期组发散/收敛、近期金叉/死叉等形态。长线趋势稳定时回调到长期组附近被视为低吸机会；短期组下穿长期组且长期组向下时提示离场。不足 60 个交易日时不给建议，面板含「不构成投资建议」免责。

**悬停详情**：鼠标在图上移动时出现**十字准线** + 跟随浮层，显示该交易日：

- 日期、单位净值、较昨日涨跌
- **最大回撤**：该日净值相对**当前所选时间段内**最高点的回撤幅度（区间高点处为 0，切换区间后重算）
- **均线读数**：顾比模式下显示短期组均值 / 长期组均值（含组内区间）与短-长乖离；关闭模式不显示均线行
- **较上次买入 / 较上次卖出**两行（该日之前最近的一次同类操作；无则基准为区间首日，并在下方注明「基准 近X月首日 <日期>」）
- 若悬停在买入/卖出点：额外显示金额、份额、持有至最新（卖出点另显示剩余份额）

**区间切换（8 档）**：近1月 / 近3月 / 近6月 / 近1年 / 近3年 / 近5年 / 近10年 / 全部（全部 = 成立至今）。切换区间会同时改变"区间首个交易日"这个兜底基准。触屏支持手指滑动查看；移出图表自动隐藏。

**图例**：基金净值 · 均线条目随模式变化（顾比：短期组 / 长期组 + 金叉 / 死叉）· **买入点** · **卖出点**（各一条，不带括号说明）；另附「较前次买入 / 较前次卖出」当前读数与口径说明（含「无上次买入/卖出记录时，基准取所选区间「近X月」的首个交易日」）。

**性能**：净值点 > 400 时顾比均线 / 组带自动抽稀采样（`gmmaStepLen = ⌈n/400⌉`，约 400 点封顶），控制 SVG 体积。

### 2.4 我的基金（表格）

列：拖拽手柄 · 基金（名称+代码，点击名称切换当前基金）· 笔数 · 相较于前次买入 · 相较于前次卖出 · 成立以来最大回撤 · 顾比信号 · 操作

| 列 | 说明 |
|---|---|
| 基金 | 名称 + 代码，**点击名称切换**到该基金的图表与记录 |
| 笔数 | 该基金的记录条数 |
| 相较于前次买入 | 最新净值相对**最后一次买入**净值的涨跌幅（含分红）；无买入记录时留空「—」，不参与排序（恒排末尾） |
| 相较于前次卖出 | 最新净值相对**最后一次卖出**净值的涨跌幅（含分红）；无卖出记录时留空「—」 |
| 成立以来最大回撤 | 全历史净值相对历史最高点的最深回撤（恒按全历史计算，不随图表区间变化） |
| 顾比信号 | 最近 **5 个交易日**（`GMMA_SIGNAL_WINDOW`）内出现顾比均线**金叉**（红▲，短期组均值上穿长期组均值）或**死叉**（绿▼，下穿）时标记提示，悬停显示信号日期；无信号或历史不足 61 个交易日时留空「—」；不参与表头排序 |
| 操作 | **置顶**（星标）· **详情**（新标签页打开天天基金该基金页面）· **更新**（重新拉取净值）· **删**（删除基金及其全部记录，需二次确认） |

排序与顺序：

- **置顶**：星标按钮，置顶基金始终排在最前，行带橙色左边条
- **拖拽排序**：拖动行首 ⋮ 手柄调整顺序（桌面端；移动端隐藏手柄，用置顶替代）
- **表头排序**：点击「相较于前次买入」「相较于前次卖出」或「成立以来最大回撤」→ 从大到小；再点 → 从小到大；第三次 → 恢复拖拽手动模式（留空的基金恒排在最后）
- **更新**：重新拉取该基金净值（刷新数据、升级为全量历史）
- **详情**：新标签页打开 `https://fund.eastmoney.com/{code}.html`（净值、评级、规模、基金经理、公告等）；被浏览器拦截弹窗时退化为当前页跳转
- 顺序、置顶、排序方式均持久化保存（旧版遗留的 `profit` 排序键在载入时归一为手动模式）

### 2.5 买卖记录

录入表单：**类型（买入/卖出）· 日期 · 金额（元）· 备注**，按钮为「添加」。

记录表列：日期 · 类型（买入/卖出徽章）· 金额 · 当日净值 · 份额 · 备注 · 较上次买入 · 较上次卖出 · 持有至最新 · 操作（改/删）

- 卖出金额即卖出回款，份额 = 金额 ÷ 当日净值
- 「较上次买入」：买入点与卖出点**统一相对上一次买入价**比较（首笔买入显示「基准」）
- 「较上次卖出」：与「较上次买入」同口径，**统一相对上一次卖出价**比较；首笔卖出在其列中显示「基准」，此前尚无卖出记录的行显示「—」
- 「持有至最新」仅买入记录显示（相对最新净值的涨跌幅）
- 非交易日（周末/节假日）自动取此前最近一个交易日的收盘净值，并在净值后标注 `*`
- 表格按日期倒序显示（最新在上）

### 2.6 批量新增（多基金批量买入/卖出）

入口：「买卖记录」卡片右上角「批量新增」。流程：

1. 选择类型（批量买入 / 批量卖出）
2. 填日期、每只金额、备注
3. 勾选要操作的基金（多选）
4. 点「添加到所选基金」→ 为所有勾选基金各创建一条相同记录

与「批量管理」（批量修改/删除）相互独立，随时切换。

### 2.7 批量管理（跨基金批量编辑）

入口：「买卖记录」卡片右上角「批量管理」。能力：

- 表格列出**所有基金**的记录，支持按基金筛选
- 全选 / 清除 / 逐条勾选，实时显示已选条数
- 对选中记录批量执行：**改日期 · 改金额 · 改备注 · 批量删除**（删除需二次确认）
- 无选中项时批量操作按钮禁用
- 再点一次「退出批量」回到普通模式

### 2.8 数据概览

四张卡片：**操作笔数**（附「买 X · 卖 Y · N 次买在更低位」）、**投入本金**（附卖出回款）、**相较于前次买入**、**相较于前次卖出**（后两张为「最新净值 vs 最后一次买入 / 卖出价」，无记录时显示 — 并注明「无买入/卖出记录」，仅供参考，不再计算总体盈亏）。

### 2.9 今天要处理

页面顶部自动列出待办提示，每条附一键处理按钮：

- 净值数据超过 3 天未更新 → 「刷新净值」
- 净值数据尚未升级为成立以来全部历史 → 「升级数据」
- 有记录但该基金净值未加载 → 「加载净值」
- 最近一次买入后跌幅 ≥ 10% → 提示可考虑补仓
- 无异常时显示「一切正常」

**忽略（消除）机制**——提醒看过即消，不常驻页面：

| 项 | 说明 |
|---|---|
| 单条忽略 | 每条提醒右侧 **×** 按钮（内联 SVG，非 emoji），点击后该条立即从页面消失 |
| 全部忽略 | 当**可忽略的提醒 ≥ 2 条**时，区块右上角出现「全部忽略」，一次写入全部消除记录 |
| 恢复 | 有待忽略项时，列表下方显示「已忽略 N 条提醒 · 恢复」；点击清除当前处于忽略状态的记录 |
| 全部忽略后的占位 | 若所有提醒都被忽略，待办区显示一条状态说明「今日待办 N 条提醒已忽略（不再常驻页面）」+「恢复」，**不留空白** |
| 持久化 | 消除记录写入 `state.dismissedTodos`，随 `data/records.json` 与 localStorage 一起保存，刷新页面、重开服务后依然生效 |
| 生效范围 | 「情境指纹」匹配才隐藏：忽略只针对**当前这一次**的情形——某只基金的净值一旦刷新过，之后再出现过期提醒会**重新提示**，不会被永久掩盖 |

**不可忽略的条目**：空态引导类提示（「开始使用：输入 6 位基金代码…」「《X》还没有买卖记录」「一切正常，没有需要处理的异常」）不提供 ×——它们不是提醒，隐藏后待办区会永久空白。它们会随状态变化自动消失。

### 2.10 查看基金详情（跳转数据源）

点每行的 **详情** 按钮 → 新标签页打开**天天基金**上该基金的页面（`fund.eastmoney.com/<基金代码>.html`），可以看净值走势、阶段涨幅、评级、规模、基金经理、分红与公告。

> 该页面属于站外页面，需要本机可访问外网；如果你的浏览器拦截了新窗口，会改为在当前页跳转。

## 三、快速开始

### 3.1 环境要求

- Node.js（任意近期版本，仅使用内置模块）
- Windows（提供 `启动.cmd`；macOS / Linux 可直接执行 `node server.js`）
- 现代浏览器

### 3.2 启动

**方式一（Windows，推荐）**：双击目录里的 `启动.cmd`

**方式二（全平台）**：

```bash
node server.js
```

看到下面的输出即启动成功：

```
====================================================
  基金买入工作台 已启动
====================================================
  访问地址：http://127.0.0.1:8765
  记录文件：.../data/records.json
  净值缓存：.../data/navCache.json
  自动快照：.../data/backups
  按 Ctrl + C 可停止服务
====================================================
```

## 四、数据存储与备份

### 4.1 分级存储

数据按"能不能再生"分开存放，重启不会丢——记录是不可再生的资产，净值只是缓存：

| 存储位置 | 说明 |
|---|---|
| `data/records.json` | **主存储**：买卖记录（只有几 KB），原子写入，带 `rev` 版本号 + localStorage 双写 + 自动快照 |
| `data/navCache.json` | 净值缓存，属于可重建数据，单只基金增量写入；删掉后点「加载净值」即可恢复 |
| `data/backups/` | 每次写入前自动生成的记录快照（5 分钟节流，保留最近 8 份） |
| 浏览器 localStorage | 兜底备份（只存记录，不再被几 MB 净值挤爆配额），key `wb_fund_workbench_records_v2`；旧 key `wb_fund_workbench_v1` 在服务端存档成功后自动释放 |

页面顶部右上角有同步状态指示：**已保存到本地** / **保存中** / **本地模式** / **保存失败**。

- **多窗口同时用**：另一个窗口改了数据，本窗口会自动同步（`storage` 事件）；万一真撞车了，会弹窗让你选"用本页数据覆盖"还是"加载对方数据"，不会悄悄丢掉一边

- 端口与数据目录可用环境变量覆盖：`FUND_WORKBENCH_PORT`、`FUND_WORKBENCH_DATA_DIR`（自动化测试用）

## 五、数据来源与接口

净值来自**天天基金（东方财富）**公开接口，覆盖**成立以来全部交易日**（不是"最近几年"），每个交易日收盘后更新。同时解析单位净值与累计净值（用于分红修正），并按时间戳对齐。

由于浏览器有跨域限制，`server.js` 作为本地代理转发请求 —— 这也是必须启动本地服务的原因。

| 接口 | 方法 | 用途 |
|---|---|---|
| `/api/ping` | GET | 健康检查（返回 `version`） |
| `/api/store` | GET | 读取记录（返回 `rev`；文件损坏时返回 `corrupt` 标记） |
| `/api/store` | POST | 保存记录（校验 `rev`，冲突返回 409 + 服务端最新数据；含待办忽略记录 `dismissedTodos`） |
| `/api/nav` | GET | 读取全部净值缓存 |
| `/api/nav?code=` | POST | 写入/更新单只基金净值（增量，不搬整包） |
| `/api/nav` | POST | 整体替换净值缓存（导入备份时使用） |
| `/api/nav?code=` | DELETE | 删除单只基金净值 |
| `/api/fund/search?key=` | GET | 基金代码或名称搜索 |
| `/api/fund/nav?code=` | GET | 基金成立以来全部净值（含累计净值 `ac`） |

> 上游请求带 15 秒超时、自动跟随重定向、非 200 直接报错。所有接口都会校验 `Host` 与 `Origin`：非本机来源一律 403。

上游若某只基金没提供累计净值，该基金的涨跌幅会自动退回单位净值口径（不影响使用，只是不体现分红）。

## 八、技术说明

### 8.1 前端架构（必须遵守）

前端严格分层，函数调用关系构成**有向无环图**：

```
数据层  Store / NavCache  记录与服务端文件、localStorage 同步
计算层  纯函数            findNavOnOrBefore / adjReturnPct / enrichRecords / summarize
                         sliceByRange / computeDrawdownMap / computeGMMA / normalizeFunds
渲染层  render*           只读 state 更新 DOM
调度层  refreshAll()      唯一刷新入口（按固定顺序调用各渲染函数）
```

- **渲染函数之间严禁互相调用**；联动的数据变化由事件处理函数改数据后调用 `refreshAll()` 统一调度
- 需要被渲染函数调用的辅助构造函数命名不得以 `render` 开头（如 `buildBulkChecks`），以保持调用方向单向
- 启动顺序：加载数据 → 初始化状态 → `refreshAll()` 一次性渲染

### 8.2 核心算法

| 算法 | 逻辑 |
|---|---|
| 当日净值匹配 | 二分查找「日期 ≤ 目标日」的最后一个交易日净值（非交易日顺延） |
| 分红修正涨跌幅 | 令 `D = 累计净值 − 单位净值`（累计每份分红），则从 from 持有到 to 的每份价值 = `to.nav + (to.D − from.D)`；两端都有 `ac` 时才修正，否则退化为纯单位净值口径 |
| 相对上次买入涨跌幅 | 买入/卖出点均与**上一次买入**的净值点比较（含分红修正）；首次买入为基准 |
| 相对上次卖出涨跌幅 | 与上同口径，与**上一次卖出**的净值点比较（含分红修正）；首笔卖出为基准 |
| 标记相对前次操作涨跌幅 | 每个买卖点分别与「上一次买入点」「上一次卖出点」比较（含分红修正）；无同类前次操作时基准取**所选区间首个净值点**（文案标注区间名），基准即自身时记 `基准` |
| 当前 vs 前次操作（列表/概览/图例） | 最新净值 vs **最后一次买入**、**最后一次卖出**的当日净值（含分红修正）；无该类型记录时为 null（前端留空） |
| 份额法盈亏（数据层保留、界面不展示） | 剩余份额 = Σ买入份额 − Σ卖出份额；`每股价值 = 最新单位净值 + (最新累计每份分红 − 买入批次加权平均累计每份分红)`；`浮动盈亏 = 剩余份额 × 每股价值 + Σ卖出回款 − Σ买入金额`；盈亏率 = 盈亏 ÷ 买入金额 |
| 区间最大回撤 | 对所选区间做单遍扫描，记录滚动最高净值，`回撤 = (当日净值 − 滚动最高) ÷ 滚动最高`（单位净值口径） |
| 成立以来最大回撤 | 对全历史做同一计算，取最小值 |
| 移动平均 | 滑动窗口求和，窗口不足 n 个交易日时为空（图上断开、浮层显示 —）；单位净值口径 |
| 顾比均线（GMMA） | 短期组 EMA 3/5/8/10/12/15、长期组 EMA 30/35/40/45/50/60；EMA 以首个 n 点简单均值为种子、`k = 2/(n+1)`，种子点前为空（图上断开）；长序列（>400 点）自动抽稀采样控制 SVG 体积 |
| 顾比形态分析 | 规则链输出建议：近期金叉+长期组向上 → 买入；死叉+长期组向下 → 卖出；多头/空头排列 → 买入/卖出；价格入长期组带内按长期组方向给回调买入/减仓；其余给持有/观望；不足 60 个交易日不给建议 |
| 顾比信号列 | `gmmaRecentCross(fund, 5)`：复用 `computeGMMA` + `findGmmaCrosses`（短期组均值上/下穿长期组均值），窗口 = 净值序列最后 5 个交易日（`GMMA_SIGNAL_WINDOW`）；命中返回最近一个交叉 `{idx, ts, type}`，历史不足 61 点或窗口内无交叉返回 null（列表留空） |
| 区间裁剪 | 按天数过滤，若不足 2 个点则回退取最后 2 个点 |

### 8.4 待办忽略的「标识 + 情境指纹」规则

每条可忽略的待办由两个字段决定是否隐藏：`key`（稳定标识）与 `sig`（当前情境指纹）。**只有 `dismissedTodos[key] === sig` 时才隐藏**，因此忽略是「情境级」而非「永久级」：

| 待办类型 | key | sig（指纹） | 含义 |
|---|---|---|---|
| 记录文件损坏 | `corrupt` | 隔离备份文件名 | 同一次损坏只忽略一次 |
| 净值缓存损坏 | `navCorrupt` | 隔离备份文件名 | 同上 |
| 净值超过 3 天未更新 | `stale:<code>` | 该基金**最新净值日期**的 ts | 净值一旦刷新，旧忽略失效；将来再超过 3 天会**重新提示** |
| 净值未升级为全部历史 | `notfull:<code>` | 最新净值 ts | 重新拉取过即视为新情境 |
| 有记录但净值未加载 | `nonav:<code>` | `n<该基金记录条数>` | 再添一笔记录后重新提示 |
| 最近一次买入后跌幅 ≥10% | `dip:<code>` | 该笔买入的 id | 只看跌不再重复打扰，下笔买入后重新评估 |

实现要点：

- 纯函数 `todoKey()` / `splitTodoItems()` / `collectTodoItems()` 归计算层；`renderTodayZone()` 只负责把 `splitTodoItems(collectTodoItems(), state.dismissedTodos)` 的结果画出来（渲染层不写数据）
- 数据变更（忽略 / 全部忽略 / 恢复）在交互层完成：改 `state.dismissedTodos` → `Store.save()` → `refreshAll()`；`splitTodoItems` 不回调任何渲染函数，调用链仍为 DAG
- 归一函数 `normalizeDismissedTodos()` 在前后端各有一份（服务端 `normalizeRecords()` 内联同名函数）：只保留字符串键值，键上限 80 字符、最多 200 条，防止异常数据撑大记录文件
- 忽略恢复的粒度是「当前处于忽略状态的那些 key」：`restoreTodoDismissals()` 只删这些键，不触碰其它记录

## 十、运维与维护须知

### 10.1 运行相关

- 应用必须保持本地服务运行（浏览器跨域限制决定了无法纯静态运行）；服务窗口关闭即停止服务
- 端口默认 `8765`，如需更换修改 `server.js` 顶部 `const PORT`
- 端口被占用时服务会友好提示并退出（不会报错中断）

### 10.2 数据相关

- 主数据文件 `data/records.json`（几 KB），可直接备份该文件迁移；净值缓存 `data/navCache.json` 可随时删除，下次加载净值会重建
- 自动快照在 `data/backups/`（最多 8 份，写入前生成）；必要时把某份快照改名为 `records.json` 即可回滚
- 旧版 `data/store.json` 首次启动会被拆分并改名为 `store.json.migrated-<时间戳>.bak`，确认新版数据无误后可自行删除
- 备份导入兼容旧版本数据（无 `type` 字段自动视为买入；`acPoints` 序列会按时间戳合并进 `points[].ac`）

### 10.3 数据源相关

- 依赖天天基金公开接口（`pingzhongdata`、`FundSearchAPI`）；若上游字段变更，需同步调整 `server.js` 中的解析正则
- 累计净值取 `Data_ACWorthTrend`（`[[时间戳, 累计净值]]`），按时间戳与单位净值对齐；上游若去掉该变量，前端会自动退化为纯单位净值口径（不崩、不误报分红）
- 上游请求带 15 秒超时、自动跟随重定向、非 200 直接报错

### 10.4 维护约束

- 新增功能时保持：单文件全内联、零外部依赖、图表手写 SVG、`refreshAll()` 统一调度、渲染函数互不调用
- 函数调用链必须保持无环（`smoke-check.js` 会校验）；需要互相触发的逻辑走"改数据 → refreshAll"
- 每次改动后必须跑通**五套测试（512 项）**再交付
- 新增/修改 API 时同步更新 `.smoke/server-test.js` 的契约断言

### 10.5 已知边界

- 拖拽排序仅桌面端可用（移动端以置顶替代）——实现依赖浏览器原生 HTML5 拖放；页面内**禁止**出现把 `-webkit-user-drag` 置为 `none` 的全局样式，`smoke-check.js` 已加断言防回归
- 记录类型仅买入/卖出两种
- 图表最大回撤在「全部」区间下等于成立以来回撤；表格列的「成立以来最大回撤」恒按全历史计算，不随区间变化
- 分红修正为**现金分红口径**（分红的现金计入收益），未模拟红利再投的份额增长，也未考虑申赎费与税费
- 卖出未校验"份额是否超过持仓"，输错金额会产生失真盈亏（待办）
- 界面已不再展示总体盈亏（份额法 `summarize()` 仍保留在数据层，作为「买在更低位」等统计与后续扩展的基础）
- 定投场景下「相较于前次买入/卖出」是**点对点**比较，不反映加权成本；如需资金加权收益（XIRR）属待办
- 均线与最大回撤仍为单位净值口径，分红除权日存在跳空
- 顾比买卖建议由固定规则从均线形态推得，**仅供参考，不构成投资建议**；均线是滞后指标，对突发事件与消息面无效；建议随最新净值实时重算，不同交易日结论可能反转
- 顾比均线 / 组带在净值点 > 400 时做抽稀采样（约 400 点封顶），均线为平滑曲线、视觉无差；若上游改为输出锯齿状数据需重新评估采样步长
- 「详情」按钮跳转的是站外页面，其内容与可用性由天天基金决定；本机无法访问外网时点击不会有内容
- 记录表「较上次买入」列仍是逐笔两两比较、首笔显示「基准」，未采用图表的区间回退规则（记录表无"区间"概念）
- `index.html` 中残留少量 `data-page-node-id` 属性（历史编辑器产物），未被任何逻辑引用，可安全清理
- 待办忽略是**情境级**：忽略「净值已 N 天未更新」后，该基金净值一旦刷新、之后再超过 3 天仍会重新提示；但若上游长期不更新（净值日期不变），忽略会一直生效——需要找回时点「恢复」
- 空态引导类提示（开始使用 / 还没有记录 / 一切正常）不提供忽略按钮，属有意设计（否则待办区会永久空白）
- `dismissedTodos` 中不再匹配任何当前待办的旧键会保留在文件里（最多几百字节，惰性数据），不影响渲染；未做主动 GC

## 十二、常见问题

**Q：双击 `启动.cmd` 出现乱码或"不是内部或外部命令"？**
早期版本的启动脚本包含中文且以 UTF-8 保存，中文控制台（GBK 编码）解析时会字节错位导致乱码。当前版本已改为纯 ASCII 脚本并自动检测 Node.js，不会再出现此问题。如果仍有异常，可在命令行进入本目录后执行 `node server.js` 作为替代启动方式。

**Q：双击后提示"端口已被占用"？**
说明服务已经在运行了（可能之前启动过）。直接用浏览器打开 http://127.0.0.1:8765 即可使用，无需重复启动。

**Q：打开页面显示不出数据？**
确认本地服务已启动（浏览器访问 http://127.0.0.1:8765/api/ping 应返回 JSON）。若显示「本地模式」，说明页面能打开但服务未响应，重启 `启动.cmd` 即可。

**Q：端口 8765 被占用？**
编辑 `server.js` 顶部的 `const PORT = 8765;` 改成其他端口（如 8766），重启后访问新端口。

**Q：想换基金？**
直接在输入框填新的 6 位代码加载即可。不同基金的买入记录互相独立，切换时自动筛选显示。

**Q：点「详情」按钮没反应？**
「详情」是跳转到**天天基金**的站外页面，需要本机能访问外网；另外它默认打开新标签页，若浏览器拦截弹窗则会改为在当前页跳转。本应用自身依然是纯本地的，跳转只在你点击时发生。

**Q：数据会上传到云端吗？**
不会。所有数据只存在你本机的 `data/` 目录和浏览器本地。联网只用于**读取**公开的净值数据，不上传任何个人信息。本地服务也只接受来自 `127.0.0.1` / `localhost` 的请求，其他网站无法读取你的持仓。

**Q：为什么分红后我的涨跌幅没有跟着净值一起掉？**
这是**故意**的。分红后单位净值下跌、但现金已进入你的口袋，所以所有涨跌幅按含分红的复权口径计算（分红被算进收益）。只有均线和最大回撤仍是单位净值口径。

**Q：为什么基金列表没有「浮动盈亏」了？**
已改成两个更直接的口径：**相较于前次买入**、**相较于前次卖出**（当前净值 vs 最后一次买入/卖出价）。没有对应记录时那一格是空的（—）。图表的买卖点旁也改成同样思路的两行数字。

**Q：数据文件在哪里？能直接改吗？**
`data/records.json`（记录）、`data/navCache.json`（净值缓存）、`data/backups/`（自动快照）。建议不要手改 JSON；迁移电脑时用界面上的「备份 / 导入」更稳妥。

**Q：提示"数据冲突"是什么意思？**
你有两个窗口（或两个标签页）同时在改数据。选"确定"用当前页面的数据覆盖，选"取消"加载另一边的数据。任何一侧都不会被静默丢弃。

**Q：提示"记录文件损坏"怎么办？**
程序已把损坏文件改名保留（`data/records.json.corrupt-*.bak`），**没有**覆盖它。可以试着用文本编辑器打开该文件抢救内容，或用之前的 `data/backups/` 快照 / 导出的备份文件恢复（把快照改名为 `records.json` 放到 `data/` 下，重启即可）。

**Q：旧版本的 `data/store.json` 呢？**
首次启动会自动拆分迁移为 `records.json` + `navCache.json`，原文件改名为 `store.json.migrated-*.bak` 保留，确认无误后可自行删除。

**Q：能多台电脑同步吗？**
当前为纯本地应用。换机器时用「备份」导出 JSON，在新机器「导入」即可迁移。

**Q：移动端能用吗？**
页面本身响应式（窄屏单列、表格转卡片、适配 iPhone 底部安全区，窄屏可用），但未做手机端的专门交互规则；拖拽排序仅桌面端可用。已知边界：记录类型仅买入/卖出两种，卖出时不会校验份额是否超过持仓。

**Q：为什么卖出记录里的金额和份额有时对不上？**
卖出金额即卖出回款，份额 = 金额 ÷ 当日净值。非交易日（周末/节假日）会取此前最近一个交易日的收盘净值并在净值后标 `*`，因此与"当天"直觉可能有差异。
