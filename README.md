# 基金买入工作台

一个**本地运行的基金操作辅助工具**：记录每一次买入与卖出，并把买卖点标注在真实净值曲线上，用来自查每次加仓相比上次是**追高**还是**抄底**，以及当前持仓的**浮动盈亏**、**均线位置**与**区间回撤**。

- 全程本地运行，数据只存在你自己电脑上，不上传云端
- 零外部依赖：无需 `npm install`，页面无框架、无 CDN、无外链字体
- 净值数据来自天天基金（东方财富）公开接口

---

## 功能特性

| # | 功能 | 说明 |
|---|---|---|
| 1 | 基金选择与净值加载 | 输入 6 位基金代码或名称片段搜索，加载该基金**成立以来全部历史净值** |
| 2 | 我的基金 | 表格管理所有基金：切换、置顶、拖拽排序、按数值排序、**跳转数据源查看详情**、更新、删除 |
| 3 | 买卖记录 | 记录每笔买入/卖出（日期、金额、备注），自动匹配当日净值并折算份额 |
| 4 | 批量新增 | 一次为多只基金添加相同的买入或卖出记录 |
| 5 | 批量管理 | 跨基金选择记录，批量改日期 / 改金额 / 改备注 / 删除 |
| 6 | 净值图表 | 净值曲线 + 买卖点两行涨跌标注 + 15/60 日均线 + 8 档区间切换 + 悬停详情 |
| 7 | 数据概览 | 操作笔数、投入本金（含卖出回款）、相较于前次买入、相较于前次卖出 |
| 8 | 数据持久化与备份 | 记录与净值缓存**分开存储**；记录自动快照 + localStorage 兜底 + 并发冲突确认；JSON 导出/导入 |

### 收益口径（重要）

- **不计算总体盈亏**，只给两个「当前净值 vs 上一次操作点」的口径：
  - **相较于前次买入** = 最新净值 ÷ 最后一次买入的当日净值 − 1
  - **相较于前次卖出** = 最新净值 ÷ 最后一次卖出的当日净值 − 1
  - 没有买入（或卖出）记录时，对应位置**留空（—）**
- 涨跌幅按**含分红的复权口径**计算：分红后单位净值下跌，若只看单位净值会把分红误判成亏损或"抄底"。（例：某基金单位净值 0.84 / 累计净值 11.2，纯净值口径会得出荒谬的 -92%）
- 份额按**单位净值**折算，代表真实买入价，不含申购/赎回费
- 均线与最大回撤仍为单位净值口径（分红除权日会有跳空）
- 上游未提供累计净值时自动退化为单位净值口径，不崩、不误报

### 图表能告诉你什么

- **买卖点标注两行**：`买 +15.0%`（相对上一次买入）/ `卖 -9.1%`（相对上一次卖出）
  - 没有"上一次"同类操作时，基准自动取**当前所选时间段的第一个交易日**，该行标注区间名，如 `买(近3月) +4.2%`；基准即该点自身时显示 `基准`
  - 买入点为红色圆点、卖出点为橙色菱形（颜色不再承载涨跌语义，涨红跌绿作用于数字）
- **均线**：15 日均线、60 日均线以虚线叠加，数据不足时自动断开
- **悬停详情**：十字准线 + 浮层，显示该交易日的日期、单位净值、较昨日涨跌、**该日相对当前区间最高点的回撤**、15/60 日均线值、**较上次买入 / 较上次卖出**两行；悬停在买卖点上时额外显示金额、份额、持有至最新（卖出点另显示剩余份额）
- **图例**：基金净值 · 15日均线 · 60日均线 · 买入点 · 卖出点，另有「较前次买入 / 较前次卖出」读数与口径说明
- **区间**：近 1 月 / 近 3 月 / 近 6 月 / 近 1 年 / 近 3 年 / 近 5 年 / 近 10 年 / 全部（全部 = 成立至今）

### 份额法统计（不展示，仅数据层保留）

`summarize()` 仍按份额法并计入现金分红计算总体盈亏，用于「N 次买在更低位」等统计与后续扩展：

```
剩余份额 = Σ买入份额 − Σ卖出份额
每股价值 = 最新单位净值 + (最新累计每份分红 − 买入批次加权平均累计每份分红)
浮动盈亏 = 剩余份额 × 每股价值 + Σ卖出回款 − Σ买入金额
```

> 界面已不再展示总体盈亏（改由「较前次买入 / 较前次卖出」替代）。

### 今天要处理

页面顶部自动列出待办，每条附一键处理按钮：

- 净值数据超过 3 天未更新 → 刷新净值
- 数据尚未升级为成立以来全部历史 → 升级数据
- 有记录但该基金净值未加载 → 加载净值
- 最近一次买入后跌幅 ≥ 10% → 提示可考虑补仓
- 无异常时显示「一切正常」

## 快速开始

### 环境要求

- Node.js（任意近期版本，仅使用内置模块）
- Windows（提供 `启动.cmd`；macOS / Linux 可直接执行 `node server.js`）
- 现代浏览器

### 启动

**方式一（Windows，推荐）**：双击目录中的 `启动.cmd`

**方式二（全平台）**：

```bash
node server.js
```

看到下面的输出即启动成功：

```
====================================================
  基金买入工作台 已启动
====================================================
  访问地址：http://127.0.0.1:8765
  记录文件：.../data/records.json
  净值缓存：.../data/navCache.json
  自动快照：.../data/backups
  按 Ctrl + C 可停止服务
====================================================
```

浏览器打开 **http://127.0.0.1:8765** 即可。建议加入书签（服务需保持运行）。

### 使用三步

1. **选基金** —— 在「选择基金」输入框填 6 位基金代码（如 `110022`），点「加载净值」；也支持输入名称片段搜索
2. **加记录** —— 在「买卖记录」里选类型（买入 / 卖出），填日期与金额，点「添加」
3. **看图表** —— 上方曲线立即出现买卖点，每个点标注相对上一次买入的涨跌幅

首次打开会预置 5 条示例数据（4 买 1 卖），可直接修改或删除。

> 必须启动本地服务的原因：浏览器存在跨域限制，净值请求需要由 `server.js` 作为本地代理转发。

## 使用指南

### 我的基金（表格）

| 列 | 说明 |
|---|---|
| 基金 | 名称 + 代码，点击名称切换到该基金 |
| 笔数 | 该基金的记录条数 |
| 相较于前次买入 | 最新净值相对**最后一次买入**净值的涨跌幅（含分红）；无买入记录时留空 |
| 相较于前次卖出 | 最新净值相对**最后一次卖出**净值的涨跌幅（含分红）；无卖出记录时留空 |
| 成立以来最大回撤 | 全历史净值相对历史最高点的最深回撤（恒按全历史计算，不随图表区间变化） |
| 操作 | 置顶（星标）· 详情（新标签页打开天天基金该基金页面）· 更新（重新拉取净值）· 删除（含全部记录，需二次确认） |

- 置顶的基金始终排在最前，行带橙色左边条
- 拖动行首 ⋮ 手柄调整顺序（桌面端；移动端隐藏手柄，以置顶替代）
- 点击「相较于前次买入」「相较于前次卖出」或「成立以来最大回撤」表头：第 1 次从大到小 → 第 2 次从小到大 → 第 3 次恢复手动拖拽模式（留空的行恒排最后）
- 顺序、置顶、排序方式均自动保存

### 买卖记录

- 录入表单：类型（买入 / 卖出）· 日期 · 金额（元）· 备注
- 卖出金额即卖出回款，份额 = 金额 ÷ 当日净值
- 「较上次买入」：买入点与卖出点统一相对**上一次买入价**比较
- 「持有至最新」仅在买入记录上显示（相对最新净值的涨跌幅）
- 非交易日（周末 / 节假日）自动取此前最近一个交易日的收盘净值，并在净值后标注 `*`
- 表格按日期倒序显示（最新在上）

### 批量新增

入口：「买卖记录」卡片右上角「批量新增」。

1. 选择类型（批量买入 / 批量卖出）
2. 填日期、每只金额、备注
3. 勾选要操作的基金（多选）
4. 点「添加到所选基金」—— 为所有勾选基金各创建一条相同记录

### 批量管理

入口：「买卖记录」卡片右上角「批量管理」。

- 表格列出所有基金的记录，支持按基金筛选
- 全选 / 清除 / 逐条勾选，实时显示已选条数
- 对选中记录批量执行：改日期 · 改金额 · 改备注 · 批量删除（需二次确认）
- 无选中项时批量操作按钮禁用

## 数据存储与备份

**按"能否再生"分级存储**——记录是不可再生的资产，净值只是缓存：

| 存储位置 | 说明 |
|---|---|
| `data/records.json` | 主存储：买卖记录（几 KB），原子写入，带 `rev` 版本号 |
| `data/navCache.json` | 净值缓存（可再生），单只基金增量写入；删掉后可重新加载 |
| `data/backups/` | 每次写入前自动生成的记录快照（保留最近 8 份） |
| 浏览器 localStorage | 兜底备份（只存记录，不再被几 MB 净值挤爆配额） |

- **并发冲突不静默覆盖**：另一个窗口改过数据时返回冲突，由你选择"用本页覆盖"或"加载对方数据"；平时靠 `storage` 事件自动同步
- **损坏文件只隔离不覆盖**：无法解析的记录文件会被改名保留为 `*.corrupt-*.bak` 并在页面提示，绝不写入示例数据把它顶掉
- **旧版自动迁移**：老版单文件 `data/store.json` 首次启动自动拆分，原文件改名为 `store.json.migrated-*.bak` 保留
- 页面右上角显示同步状态：**已保存到本地** / **保存中** / **本地模式** / **保存失败**
- **备份 / 导入**：导出含记录与净值的完整 JSON；导入条数无上限，均有二次确认
- 数据累计 ≥ 30 条时提醒导出备份

### 数据结构

```jsonc
// data/records.json
{
  "version": 2, "rev": 12,
  "records": [ { "id": "", "code": "", "type": "buy | sell", "date": "", "amount": 0, "note": "" } ],
  "currentCode": "110022", "fundOrder": [], "fundPinned": {}, "fundSort": { "key": "", "dir": "desc" },
  "savedAt": 0
}

// data/navCache.json
{
  "version": 2,
  "funds": { "110022": {
    "name": "...", "full": true, "inceptionTs": 0, "updatedAt": 0,
    "points": [ { "ts": 0, "nav": 1.0, "daily": 0.5, "ac": 1.5 } ]   // ac = 累计净值
  } }
}
```

导入兼容旧版本数据（缺少 `type` 的记录视为买入；旧的 `acPoints` 序列会按时间戳合并进 `points[].ac`）。

## 数据来源与接口

净值来自**天天基金（东方财富）**公开接口，覆盖**成立以来全部交易日**，每个交易日收盘后更新。同时解析单位净值与累计净值（用于分红修正），并按时间戳对齐。

| 接口 | 方法 | 用途 |
|---|---|---|
| `/api/ping` | GET | 健康检查 |
| `/api/store` | GET / POST | 读取 / 保存记录（POST 带 `rev`，冲突返回 409） |
| `/api/nav` | GET / POST / DELETE | 读取 / 写入 / 删除净值缓存（`?code=` 单只增量写入） |
| `/api/fund/search?key=` | GET | 基金代码或名称搜索 |
| `/api/fund/nav?code=` | GET | 基金成立以来全部净值（含累计净值） |

上游请求带 15 秒超时、自动跟随重定向、非 200 直接报错。

## 安全

本应用只在本机回环地址上运行，且：

- 只监听 `127.0.0.1`
- 校验 `Host` 头（防 DNS rebinding）与 `Origin` 头，非本机来源一律 403
- **不下发任何 CORS 响应头** —— 否则任意网站都能读写你本机的持仓数据
- 静态资源做了目录穿越防护
- `.gitignore` 排除 `data/`，个人持仓不会进入版本库

## 技术说明

| 项 | 说明 |
|---|---|
| 形态 | 本地 Web 应用：本机启动 Node 服务，浏览器访问 `http://127.0.0.1:8765` |
| 前端 | 单文件 HTML（`public/index.html`），CSS / JS / 图表 / 图标全部内联，零外部依赖 |
| 后端 | `server.js`，仅使用 Node 内置模块（`http` / `https` / `fs` / `path` / `url`），无需 `npm install` |
| 数据源 | 天天基金（东方财富）公开接口，由本地服务代理转发（单位净值 + 累计净值） |
| 存储 | 记录 `data/records.json`（双写 + 快照 + rev 并发校验）与净值缓存 `data/navCache.json`（可再生）分离 |
| 安全 | 仅监听 `127.0.0.1`，校验 `Host`/`Origin`，不下发 CORS 头 |

前端严格分层，调用关系构成有向无环图：

```
数据层  Store / NavCache  记录与服务端文件、localStorage 同步
计算层  纯函数            findNavOnOrBefore / adjReturnPct / enrichRecords / summarize
                         sliceByRange / computeDrawdownMap / computeMA / normalizeFunds
渲染层  render*           只读 state 更新 DOM
调度层  refreshAll()      唯一刷新入口（按固定顺序调用各渲染函数）
```

核心算法：

| 算法 | 逻辑 |
|---|---|
| 当日净值匹配 | 二分查找「日期 ≤ 目标日」的最后一个交易日净值（非交易日顺延） |
| 分红修正涨跌幅 | `D = 累计净值 − 单位净值`；从 from 到 to 的每份价值 = `to.nav + (to.D − from.D)`；两端缺 `ac` 时退化为单位净值口径 |
| 相对上次买入涨跌幅 | 买卖点均与**上一次买入**的净值点比较（含分红修正）；首次买入为基准 |
| 份额法盈亏 | 见上文「盈亏算法」 |
| 区间最大回撤 | 单遍扫描记录滚动最高净值，`回撤 = (当日净值 − 滚动最高) ÷ 滚动最高` |
| 移动平均 | 滑动窗口求和，窗口不足 n 个交易日时为空（图上断开、浮层显示 `—`） |
| 区间裁剪 | 按天数过滤，不足 2 个点则回退取最后 2 个点 |

## 常见问题

**Q：双击 `启动.cmd` 出现乱码或「不是内部或外部命令」？**
早期版本的启动脚本含中文并以 UTF-8 保存，在 GBK 编码的中文控制台会字节错位。当前版本已改为纯 ASCII + CRLF 并自动探测 Node.js。若仍异常，可在命令行进入目录执行 `node server.js`。

**Q：提示「端口 8765 已被占用」？**
说明服务已在运行。直接用浏览器打开 http://127.0.0.1:8765 即可，无需重复启动；服务本身也会以退出码 0 友好退出。

**Q：页面显示不出数据？**
先确认服务已启动：访问 http://127.0.0.1:8765/api/ping 应返回 JSON。若页面显示「本地模式」，说明页面能打开但服务未响应，重启 `启动.cmd` 即可。

**Q：想换端口？**
修改 `server.js` 顶部的 `const PORT = 8765;`，重启后访问新端口。

**Q：数据会上传到云端吗？**
不会。数据只存在本机 `data/` 目录与浏览器本地。联网仅用于**读取**公开净值数据；本地服务只接受来自 `127.0.0.1` / `localhost` 的请求，其他网站无法读取你的持仓。

**Q：为什么分红后我的盈亏没有跟着净值一起掉？**
这是**有意的口径**：分红后单位净值下跌但现金已到账，因此涨跌幅与盈亏按含分红的复权口径（累计净值）计算；只有均线与最大回撤仍是单位净值口径。

**Q：提示「数据冲突」怎么办？**
说明你有两个窗口同时在改数据。确认 = 用当前页面数据覆盖，取消 = 加载另一边数据，任何一侧都不会被静默丢弃。

**Q：提示「记录文件损坏」怎么办？**
损坏文件已被改名保留（`data/records.json.corrupt-*.bak`），没有被覆盖。可用它抢救内容，或从 `data/backups/` 快照（改名为 `records.json` 放回 `data/`）恢复。

**Q：旧版本的 `data/store.json` 呢？**
首次启动会自动拆分迁移为 `records.json` + `navCache.json`，原文件改名为 `store.json.migrated-*.bak` 保留，确认无误后可自行删除。

**Q：能多台电脑同步吗？**
当前为纯本地应用。换机器时用「备份」导出 JSON，在新机器「导入」即可迁移。

**Q：移动端能用吗？**
页面本身响应式（窄屏单列、表格转卡片、适配 iPhone 底部安全区，窄屏可用），但未做手机端的专门交互规则；拖拽排序仅桌面端可用。

## 维护约定

修改本项目时请保持以下约束：

- 单文件全内联、零外部依赖、图表手写 SVG
- `refreshAll()` 为唯一刷新入口，渲染函数之间严禁互相调用（辅助构造函数命名不得以 `render` 开头）
- 函数调用链必须保持无环（`smoke-check.js` 会做 DAG 校验）
- 新增功能后跑通五套测试（414 项）再交付；改动接口时同步更新 `.smoke/server-test.js`

若上游接口字段变更，需同步调整 `server.js` 中的解析正则。

### 已知边界

- 分红修正按**现金分红口径**，未模拟红利再投的份额增长，也不含申赎费与税费
- 卖出时不校验份额是否超过持仓，输错金额会产生失真盈亏
- 界面不再展示总体盈亏；「相较于前次买入/卖出」为点对点比较，不等价于资金加权收益率（XIRR）
- 均线与最大回撤仍为单位净值口径，分红除权日存在跳空
- 拖拽排序仅桌面端；记录类型仅买入/卖出两种
- 「详情」按钮跳转到站外页面（天天基金），其内容与可用性由该站点决定，本机需能访问外网
